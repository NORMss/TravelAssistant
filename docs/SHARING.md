# Готовые маршруты и приватность

Пользователь собрал маршрут и хочет им поделиться. Кто-то другой хочет его
скачать и поехать. Между этими двумя желаниями стоит одна проблема, и она
важнее всей остальной функциональности раздела.

## Проблема

План поездки — это не только адреса. Это номер брони и PIN, код рейса и номер
багажной квитанции, фамилия на стойке регистрации, город вылета, название
отеля и даты, когда человека там не было дома. Опубликовать такой файл —
значит опубликовать инструкцию по слежке за собой.

Проверено на реальных данных: в личном плане поездки, который лёг в основу
демонстрационного маршрута, нашлись фамилия владельца, два номера брони, PIN,
код заказа авиабилета, номер багажной квитанции, почта отеля и город вылета.
182 текстовых поля из 780 содержали личные подробности.

## Решение: два слоя, а не чистка

Очевидный путь — «выгрузить план и вычистить личное» — ненадёжен. Чёрный
список ломается от одного незамеченного поля, а полей сотни.

Поэтому слоёв два, и они **разные типы**:

| | `Trip` (личный слой) | `TripTemplate` (публичный слой) |
|---|---|---|
| Даты | конкретные | относительные: «День 1» |
| Брони, PIN, рейсы | есть | **полей не существует** |
| Участники | есть | **поля не существует** |
| SOS-карточка | есть | **поля не существует** |
| Заметки | личные | только авторский `tip` |
| Фотографии | есть | **поля не существует** |
| Отметки «сделано» | есть | нет |
| Поля синхронизации | есть | нет |

Утечка через шаблон невозможна не потому, что мы аккуратны, а потому, что в
типе нет полей, куда личное можно было бы положить. Публикация — это не
экспорт поездки: шаблон собирают заново, сознательно выбирая, что показать.

## Демонстрационный маршрут

`core/data/src/main/assets/templates/beijing-6-days.json` — шесть дней по
Пекину: 54 этапа, 19 мест, 123 фразы, 20 развилок, пять списков сборов,
30 карточек бинго. Адреса иероглифами с координатами.

Собран скриптом `tools/make_demo_template.py` из личного плана. Скрипт работает
**белым списком**: копирует только перечисленные поля, всё незнакомое не
переносит. Дополнительно выброшены:

* отель и этапы заезда-выезда — «где этот человек ночевал в эти даты» самый
  опасный объект в плане;
* конкретные рейсы и город вылета;
* фразы с фамилией и с размером группы;
* все заметки автора — вместо них восемь свежих подсказок, написанных для
  шаблона.

Второй рубеж — `DemoTemplatePrivacyTest` в `core:data`. Он читает файл, который
реально уедет в публичный репозиторий, и падает, если найдёт фамилию, почту,
код рейса, номер брони, длинную цифровую последовательность или конкретную
дату. Скрипт можно сломать правкой и забыть перезапустить; тест — нет.

```bash
python3 tools/make_demo_template.py ../BeijingTrip/app/src/main/assets/trip.json
./gradlew :core:data:testDebugUnitTest
```

Запускать оба шага вместе. Один без другого бессмысленен.

## Что будет дальше

Каталог пока читает только встроенные шаблоны. Публикация и скачивание чужих —
фаза 6 ([ROADMAP.md](ROADMAP.md)), и в ней есть несколько решений, которые
стоит принять заранее.

**Перед публикацией — предпросмотр.** Пользователь должен увидеть ровно тот
текст, который уедет наружу, с явным списком «вот это мы убрали». Публикация
в один тап без предпросмотра — та самая ошибка, от которой защищает весь
остальной дизайн.

**Чужой текст — чужой.** Скачанный шаблон показывает подсказки автора как
цитаты, а не как указания приложения. Это и вопрос доверия, и вопрос
ответственности: в чужом совете может быть неточность или злой умысел.

**Ссылка автора проверяется.** `TemplateAuthor.link` при импорте допускается
только со схемой `http(s)` и открывается через системный браузер, а не внутри
приложения.

**Размер — тоже защита.** Шаблон на сотню мегабайт либо ошибка, либо атака.
Разумный предел — единицы мегабайт; всё, что больше, отклоняется при импорте.
