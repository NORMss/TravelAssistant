# Интерфейс

Одна мысль, из которой следует всё остальное: **приложением пользуются стоя,
одной рукой, в незнакомом месте, часто на солнце и часто на нервах.** Отсюда
крупные цели нажатия, читаемый контраст, минимум экранов между вопросом и
ответом — и ни одного действия, которое нельзя отменить.

## Material 3 Expressive

Тема — `MaterialExpressiveTheme`, а не `MaterialTheme`
(`core/designsystem/theme/Theme.kt`). Разница не в наборе компонентов, а в
значениях по умолчанию: схема движения становится `expressive`, и все
material-компоненты начинают двигаться пружинами с лёгким перелётом.

### Цвет

Своей фирменной палитры у приложения нет. На Android 12+ схему задают обои
пользователя (`dynamicLightColorScheme` / `dynamicDarkColorScheme`). Запасная
палитра включается только на старых версиях и когда пользователь выключил
динамику сам.

Следствие, о котором легко забыть: **опираться на конкретный цвет нельзя.**
Если на экране две сущности различаются только оттенком, на чужих обоях они
сольются. Различать нужно формой, размером и положением; цвет — подсказка,
а не носитель смысла.

Роли, которых в Material-схеме нет (развилка «по плану / обход / отмена»,
«срочно»), выводятся из текущей схемы в `TravelAccents`, а не задаются
константами — иначе на динамических цветах они торчали бы чужеродным пятном.

### Движение

Спеки берутся из `Motion` (`core/designsystem/theme/Motion.kt`), а не пишутся
по месту:

```kotlin
val scale by animateFloatAsState(target, animationSpec = Motion.fastSpatial())
```

* `spatial` — для того, что двигается и меняет размер. Перелёт здесь к месту.
* `effects` — для цвета, прозрачности, тени. Перелёт по цвету выглядит грязно.

`tween(300)` в коде экрана — повод для правки: перелёт у одного элемента и
ровная кривая у соседнего читаются как баг.

### Форма

`MaterialShapes` даёт 35 форм. Они закреплены за смыслом в `TravelShapeTokens`,
а не выбираются на месте:

| Токен | Форма | Что |
|---|---|---|
| `cover` | Cookie9Sided | Обложка поездки |
| `avatar` | Circle | Участник |
| `activeStop` | Clover4Leaf | Текущий этап — единственный элемент такой формы на экране |
| `placePin` | Pill | Метка места |
| `empty` | Flower | Пустое состояние |

Правило: одна сущность — одна форма во всём приложении. Форма здесь работает
там, где цвет работать не может.

## Плавающие элементы

Это главное отличие от прошлого приложения и основной источник «ощущения
свободы».

**Чего нет:** `Scaffold` с `bottomBar`. Прибитая панель отрезает себе полосу
экрана, и список всегда заканчивается над ней.

**Что вместо:** `FloatingNavBar` — пилюля на `HorizontalFloatingToolbar`,
висящая над контентом. Содержимое идёт под ней до самого низа; чтобы последний
элемент не прятался, экраны получают `contentPadding` из `TravelApp`.

```kotlin
// app/navigation/TravelApp.kt
val screenPadding = PaddingValues(
    bottom = insets.calculateBottomPadding() + FLOATING_UI_HEIGHT,
    …
)
```

Любой скроллящийся экран обязан принять `contentPadding` параметром и отдать
его в `LazyColumn`/`verticalScroll`. Экран, который этого не делает, прячет
свою последнюю строку под навигацией.

**Главное действие** — `TravelFabMenu` на `FloatingActionButtonMenu`: пункты
вылетают из кнопки пружиной, кнопка морфится в крестик, фон гаснет. Состоянием
раскрытия владеет экран — его нужно сбрасывать при навигации и при системном
«назад».

**Подпись только у выбранного раздела.** Шесть подписей в пилюле не поместятся
ни на одном телефоне, а иконка выбранного раздела без подписи неоднозначна.

## Чипы

Чип выбирает не пункт меню, а **ракурс на те же данные**, и остаётся на виду,
пока пользователь смотрит результат. Поэтому лента чипов скроллится и не
прячется в выпадающий список: выбранное должно быть видно без дополнительного
касания.

* `ChipRow` — дни поездки, категории этапов, фильтры мест.
* `ActionChip` — действие над объектом: «Скопировать», «На карте», «Отправить».

## Текст на языке места

У него свой кегль — `LocalScriptMedium` / `LocalScriptLarge`, а не `bodyLarge`
пожирнее. Причина: его показывают **не себе, а собеседнику** — с другой стороны
стола, иногда при плохом зрении. Иероглифы и деванагари нельзя сжимать по
межстрочному, поэтому `lineHeight` задан с запасом, а не множителем.

## Подсказки

`core/designsystem/component/Coachmark.kt` — затемнение с вырезом вокруг
элемента и карточка с объяснением. Своё, а не библиотека: готовые решения
приносят свои кривые анимации, а здесь движение обязано приходить из
`MotionScheme` темы, иначе подсказка выглядит вставкой из чужого приложения.

Правила: не больше трёх шагов на экран, подсказка объясняет неочевидное,
тур пропускается одним нажатием и не возвращается. Ключи — значения `GuideKey`,
а не строки: опечатка в строке даёт подсказку, которая либо не покажется
никогда, либо покажется каждый раз, и компилятор такое не поймает.

## Доступность

Проверяется не в конце, а при написании компонента:

* Любая иконка-кнопка имеет `contentDescription`. Если рядом есть видимая
  подпись — описание у иконки **убирается**, иначе скринридер читает раздел
  дважды.
* Раскрывающееся меню FAB отдаёт свои пункты через `customActions`: скринридеру
  не нужно раскрывать меню, чтобы добраться до действия.
* Все превью идут через `@TravelPreviews` — светлая, тёмная и крупный шрифт
  сразу. Компонент, который разваливается при `fontScale = 1.5`, не готов.
* Цель нажатия — минимум 48 dp. Material-компоненты дают это сами; свои —
  нет, им нужен `Modifier.minimumInteractiveComponentSize()`.

## Адаптивность

Подключён `material3-adaptive`. Пока все экраны однопанельные; раскладка на
планшете и складном — фаза 3 (`ListDetailSceneStrategy` из
`adaptive-navigation3` + `WideNavigationRail` вместо плавающей пилюли на
широком экране). Скилл `adaptive` установлен в проект.

## Чек-лист нового экрана

1. Принимает `contentPadding: PaddingValues` и отдаёт его в скролл.
2. Состояние — один `UiState` из ViewModel, а не три `remember` в composable.
3. Пустое состояние написано **до** основного: его увидят первым.
4. Анимации — через `Motion`, формы — через `TravelShapeTokens`.
5. Превью с `@TravelPreviews`.
6. Ни одного жёсткого цвета — только роли из `MaterialTheme.colorScheme` и
   `TravelTheme.accents`.
7. Если на экране есть неочевидное — завести `GuideKey` и короткий тур.
