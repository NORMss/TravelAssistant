# Travel Assistant

Приложение для путешествий: план поездки, который работает офлайн, и языковая
модель, которая помогает этот план собрать и переделать на ходу.

Наследник BeijingTrip — приложения, написанного под одну поездку
вчетвером в Пекин. Там всё было зашито в APK: один город, один язык, один часовой
пояс, одна бронь. Здесь то же самое, но для любой поездки, любого языка и любого
количества участников.

> Статус: скелет. Сборка, навигация, база, тема и каркас модулей работают;
> разделы наполняются по [docs/ROADMAP.md](docs/ROADMAP.md).

## Собрать и запустить

```bash
./gradlew :app:assembleDebug
android run --apks app/build/outputs/apk/debug/app-debug.apk
```

Эмулятор, если его ещё нет:

```bash
android emulator list
android emulator start <avd>
```

Тесты:

```bash
./gradlew test testDebugUnitTest
```

## Устройство в двух словах

Локальная база — источник правды. Сеть опциональна и всегда пишет в базу, а не в
обход: приложение обязано работать в самолёте и в стране, где половина сервисов
недоступна. У каждой записи с первого дня есть `updatedAt`, `deletedAt` и
`remoteRevision` — синхронизации ещё нет, но добавить её потом, не переписав всё,
можно только так.

Модель никогда не пишет в план напрямую. Она возвращает текст, из которого
собирается список изменений, и пользователь нажимает «Применить» сам. То же
правило у распознавания достопримечательностей: подпись к снимку — предложение,
пока человек её не подтвердил.

Личное и публичное разделены типами, а не аккуратностью: в `TripTemplate`,
который уезжает наружу, просто нет полей для броней, рейсов и участников.
Подробности — [docs/SHARING.md](docs/SHARING.md).
