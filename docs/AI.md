# Модели и агенты

Два разных вопроса, которые легко перепутать:

1. **Модель внутри приложения** — чем пользуется путешественник.
2. **Агенты в разработке** — чем пользуемся мы, собирая это приложение.
   Про второе — [TOOLING.md](TOOLING.md).

Здесь про первое.

## Главное правило

**Модель никогда не пишет в план напрямую.**

Она возвращает текст. Из текста собирается `PlanProposal` — список «что
добавится, что изменится (с точностью до поля), что удалится». Пользователь
видит этот список и нажимает «Применить» сам.

Это не осторожность ради осторожности. В BeijingTrip наблюдался конкретный
случай: модель оборвала ответ на середине, и половина поездки выглядела как
удалённая. Экран подтверждения существует из-за него.

## Четыре уровня

### 1. Обмен текстом — работает без всего

Ничего не нужно: ни ключа, ни сети, ни поддерживаемого телефона. План
выгружается в Markdown, уезжает в любой чат с моделью, правленый возвращается
обратно.

Формат — `core/ai/exchange/PlanMarkdown.kt`:

```markdown
## Прилёт и Асакуса {#day-1}
Дата: 2026-04-10
Подпись: День 1

### 09:30 · 浅草寺 · Храм Сэнсо-дзи {#stop-1}
Подпись: Храм Сэнсо-дзи
Тип: SIGHT
Длительность: 90 мин
Адрес: 東京都台東区浅草2-3-1
Координаты: 35.71480, 139.79670
Чтение: Sensō-ji
Метка: вход свободный
```

**Почему Markdown, а не JSON.** Измерено на прошлом приложении: весь план в
JSON — 240 КБ, один день в Markdown — 6–14 КБ. Разница не только в размере.
JSON ломается от одной пропущенной запятой, и модель правит его неуверенно;
Markdown она правит уверенно, и его видно глазами до применения.

**Якоря `{#id}`** — то, что превращает круговой обход в правку, а не в замену:
запись с якорем обновляется, без якоря — добавляется, пропавшая — удаляется.
Молчание при этом не считается удалением: блок считается удалённым, только если
в тексте вообще были блоки этого вида.

Статус: **экспорт готов и покрыт тестами. Разбор обратно — первая задача фазы 4**
(интерфейс `PlanImporter` в `core/ai/exchange/PlanExchange.kt`, контракт описан).

### 2. Gemini Nano на устройстве — подключён

`core/ai/provider/OnDeviceLlmProvider.kt`, ML Kit GenAI Prompt API.

Бесплатно, офлайн, план не уходит наружу. Работает в самолёте и в стране с
заблокированными сервисами. Ограничения существенные: контекст порядка 4k
токенов и качество ниже облачного — поэтому его дело короткие задачи:

* перевести фразу под ситуацию,
* сжать заметку,
* предложить, чем заменить закрытый музей,
* подобрать формулировку для местного.

Доступность проверяется **каждый раз** (`checkStatus()`): модели нет на части
телефонов, а где есть — её может потребоваться скачать. Это нормальный путь,
а не ошибка; экран настроек показывает состояние и кнопку загрузки.

Скилл `ml-kit-genai-prompt-api` установлен в проект.

### 3. Облачная модель — в каталоге, не подключена

Две развилки, обе записаны, выбор не сделан:

* **Firebase AI Logic** (`com.google.firebase:firebase-ai`) — Gemini Pro/Flash
  без своего бэкенда и **без ключа в APK**. Нужен проект Firebase и платёж по
  мере использования.
* **Свой ключ пользователя (BYOK)** — пользователь вводит ключ Gemini, Anthropic
  или OpenAI. Платит он, приложение остаётся бесплатным. Хранилище уже готово:
  `core/datastore/SecretStore.kt` шифрует ключ через Android Keystore, в
  DataStore попадает только шифртекст.

Рекомендация: **начать с BYOK.** Приложение локальное и открытое; свой бэкенд
и платёжный аккаунт на старте — лишняя сущность. Firebase добавить позже, когда
появится понятный сценарий «пользователь не хочет возиться с ключами».

> API-ключ никогда не зашивается в APK. Даже в debug-сборке. Из APK его
> достают за минуту.

### 4. Агенты внутри приложения — фаза 5

* **ADK Kotlin для Android** (`com.google.adk:google-adk-kotlin-core-android`)
  — агентный рантайм внутри приложения: `LlmAgent`, инструменты через `@Tool`,
  сессии. Позволяет сделать «спланируй день» не одним промптом, а агентом с
  инструментами «посмотри план», «найди место рядом», «проверь, влезает ли по
  времени».
* **A2UI** (`androidx.a2ui.*`, `material3-a2ui`) — агент возвращает **описание
  интерфейса** в JSON по протоколу A2UI, библиотека рендерит его нативными
  Compose-компонентами из объявленного каталога. Произвольный код не
  выполняется. Для нас это «модель предлагает три варианта дня карточками с
  кнопками», а не стена текста.
* **AppFunctions** (`androidx.appfunctions`, Android 16+) — приложение как
  **MCP-сервер для системного Gemini**: «добавь в мою поездку ужин в четверг в
  семь» выполняется, не открывая приложение. Функции описываются KDoc и
  аннотацией `@AppFunction`. Скилл `appfunctions` установлен.
* **MCP Kotlin SDK** (`io.modelcontextprotocol:kotlin-sdk`) — вторая сторона
  того же: приложение как **клиент** MCP, ходящий к удалённым серверам
  (расписания, бронирования, погода). Нужен, если понадобятся данные, которых
  нет в самом приложении.

## Абстракция провайдеров

`core/ai/LlmProvider.kt`. Экран не знает, с кем говорит:

```kotlin
interface LlmProvider {
    val id: String
    val capabilities: LlmCapabilities      // onDevice, requiresApiKey, vision, tools…
    suspend fun availability(): LlmAvailability
    fun generate(request: LlmRequest): Flow<LlmChunk>
}
```

Поток, а не `suspend fun`: ответ идёт частями, и ждать его целиком со спиннером —
это десятки секунд пустого экрана.

Провайдеры собираются в множество через Hilt-мультибиндинг. Новый провайдер —
одна строка `@Binds @IntoSet`; ни реестр, ни экран настроек, ни ассистент при
этом не меняются. `LlmRegistry.bestAvailable()` предпочитает то, что работает
без сети и без ключа: приложение должно быть полезно сразу после установки.

## Промпты

Лежат в `core/ai/prompt/Prompts.kt` под контролем версий. Это такой же код, как
остальной, и ломается он так же — молча и в ответе пользователю.

Главное правило в системной части: **запрет выдумывать.** Вымышленный адрес
музея — это потерянный день поездки, а не неточность в ответе. Если модель не
уверена, она обязана сказать «нужно проверить» и оставить поле пустым.

## Приватность

Что должно быть видно пользователю до первого запроса:

| Провайдер | Куда уходят данные |
|---|---|
| Обмен текстом | Туда, куда пользователь сам вставил |
| Gemini Nano | Никуда, всё на устройстве |
| BYOK | К выбранному провайдеру по ключу пользователя |
| Firebase AI Logic | В Google через проект Firebase |

Это же пойдёт в Data Safety при публикации в Google Play. Скилл
`play-policy-insights` установлен и умеет сверять объявленное с кодом.
